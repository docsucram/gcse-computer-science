AQA §3.7.1

Data Redundancy

Unnecessary duplication of data. In a flat-file database, storing pupil addresses 3–5 times consumes extra storage space and slows backups. Relational databases eliminate redundancy by storing personal details strictly once in a parent entity.

Core Exam Trap

The 3 Database Anomalies

• Update Anomaly: Changing data in 1 row leaves older data in other rows (inconsistent records).
• Deletion Anomaly: Deleting a subject accidentally erases the student's entire profile.
• Insertion Anomaly: Cannot record a new subject until a student enrolls onto it.

Key Concept

Primary & Foreign Keys

• Primary Key (PK): A field that uniquely identifies each record in its table (e.g. StudentID).
• Foreign Key (FK): A primary key from another table used to establish a relationship without repeating full personal details.

Relational Database & SQL Query Workbench

Structured Query Language (SQL) is the standard declarative language used to search, filter, and extract data from relational tables. Using commands like SELECT, FROM, and WHERE, queries retrieve exact matching records without altering the underlying data.

Why Do We Need Relational Databases?

Imagine writing a student's full name, address, and form group next to every single exam they ever sit. If Alice takes 10 exams, her details would be repeated 10 times! If she moves house, updating 10 rows risks errors. In a Relational Database, we store student details once in the Students table, and link their exam results using a Foreign Key.

Tables and Records

A table holds records (rows) and fields (columns). Separating tables prevents data redundancy (unnecessary duplication).

Primary vs Foreign Keys

Primary Key (PK): Unique ID in its own table.
Foreign Key (FK): Links back to the PK of another table to connect records.

Relational Database Revision & Exam Traps

Key definitions, table relationships, and SQL exam traps for Paper 2 (§3.7). Review primary vs foreign keys, entity-relationship models, data redundancy, and standard SQL syntax.

Key Exam Traps & Core Concepts

EXAM DEFINITION 1: RELATIONAL KEYS

Primary Key vs Foreign Key

Examiners frequently ask for definitions of primary and foreign keys. Be precise with your wording:

Primary Key (PK):
• A field (or attribute) that uniquely identifies each individual record in a table.
• Example: StudentID in the Students table.
Foreign Key (FK):
• An attribute in one table that is the primary key of another table, used to establish a link/relationship between the two tables.
• Example: ExamResults.StudentID.
Mark Scheme Tip: Never say a foreign key is just "a key in another table". You must state it is a primary key from one table placed into another to create a relationship.
EXAM TRAP 2: DATA INTEGRITY

Why Split Data into Multiple Tables? (Flat File vs Relational)

A classic 3-mark question: "Explain one advantage of using a relational database rather than a flat-file database."

• Reduces Data Redundancy: Data is not duplicated unnecessarily across multiple rows.
• Prevents Update Inconsistencies: If Alice changes form room, it is updated in one place only (in the Students table), rather than across 10 different exam entries.
• Smaller File Size & Faster Queries: Less duplicate text means less storage used.
EXAM TRAP 3: SQL SYNTAX RULES

Quotes Around Strings vs Numbers

In SQL, text and character data types must always be wrapped in single quotes ('Computing' or '11A'). Numeric integers (such as Score >= 80 or YearGroup = 11) must not have quotes.

✓ Correct: WHERE Subject = 'Computing' AND Score >= 80
✗ Wrong: WHERE Subject = Computing AND Score >= '80'
