How the CPU Actually Works (Key Registers & Theory)

The Central Processing Unit (CPU) is the computer's engine. Every second, it repeats the Fetch-Decode-Execute cycle billions of times: fetching an instruction from memory, decoding what it means, and executing it.

The Desk Analogy (Registers vs RAM): RAM is like a massive library down the street—it holds everything, but fetching from it takes time. Registers are like sticky notes right on your desk. Ultra-fast, but each only holds one tiny piece of data.
Key Registers to Remember:
• PC (Program Counter): Address of the NEXT instruction.
• MAR: Address in RAM we are reading/writing.
• MDR: Holds data/instruction fetched from or sent to RAM.
• CIR: Holds instruction currently being decoded and executed.
• ACC (Accumulator): Holds temporary calculation results.

The Three Major CPU Performance Factors — Exam Essentials

1
Clock Speed — The CPU Heartbeat

Clock speed is measured in Hertz (Hz or GHz) and represents the frequency of electrical pulses generated by the system clock. 1 GHz equals one billion Fetch-Decode-Execute cycles every single second. A higher clock frequency allows the CPU to process more instructions per second, leading to faster program execution.

Exam Warning: Higher clock speeds consume substantially more electrical power and generate intense heat. If cooling systems cannot dissipate this heat fast enough, the CPU automatically throttles down (slows its frequency) to prevent permanent hardware damage.
2
Cache Memory — On-Chip Desk vs Off-Chip Library

Cache is high-speed Static RAM (SRAM) constructed directly on the CPU silicon die, providing sub-nanosecond access latency. Frequently used instructions and data are kept here. When data is found in cache (a Cache Hit), the processor retrieves it immediately without pausing. Main memory (RAM) is located across the motherboard bus and takes roughly 70ns. When data is missing from cache (a Cache Miss), the CPU must stall and wait for bus transfer.

Exam Tip: A computer cannot simply replace all RAM with 64 GB of cache because SRAM requires multiple transistors per bit, making it physically too large for a silicon die and far too expensive to manufacture at scale.
3
Number of Cores — Parallel Processing

Each CPU core contains its own independent Arithmetic Logic Unit (ALU), Control Unit (CU), and internal registers. A quad-core processor can execute four distinct instructions simultaneously.

Key Exam Trap — Why doubling cores does not simply double speed:
  • Software must be written for multithreading; single-threaded programs can only run on one core while remaining cores stay completely idle.
  • Thread coordination and core-to-core communication introduce management overhead.
  • All cores contend for the same shared memory bus, shared cache levels, and RAM bandwidth.
Advanced Extension

Beyond GCSE — How Modern CPUs Eliminate Idle Stalls

In a classic Fetch-Decode-Execute design, functional sub-units (such as the ALU or instruction decoder) frequently sit completely idle while waiting for high-latency memory or conditional outcomes. Modern high-performance processors use advanced hardware engineering to keep execution units continuously busy:

Branch Prediction and Speculative Execution

When a program reaches an IF / ELSE condition or loop, the CPU encounters a branch. Rather than sitting idle waiting for the condition to be calculated, modern CPUs predict which path the code will take (often with over 95% accuracy) and execute instructions ahead of time along the predicted path. If the prediction is verified correct, execution proceeds without delay. If incorrect, the speculative work is discarded and the pipeline restarts on the correct path.

Instruction Pipelining

Operating like an industrial assembly line, the CPU divides instruction processing into overlapping stages. While instruction 1 is in the Execute stage, instruction 2 is simultaneously being Decoded, and instruction 3 is already being Fetched from cache. This overlap ensures every internal functional unit performs work on every single clock cycle.

Out-of-Order Execution (OoO)

When an instruction stalls awaiting data from slow system RAM, modern processors do not freeze the entire core. Hardware schedulers scan forward in the instruction queue, identify later instructions that do not depend on the missing data, and execute them out of original program order to prevent wasted clock cycles.

Why Secondary Storage is Essential

The CPU can only directly fetch instructions from Primary Storage (RAM & Cache). However, a computer with only RAM and ROM would be practically useless for two critical reasons:

⚡

1. RAM is Volatile (Data Retention)

Because RAM requires a continuous electrical charge to refresh its capacitors, all data is permanently lost when the computer powers off or sleeps. Secondary storage is non-volatile, keeping your operating system, installed software, games, photos, and saved work permanently preserved for decades.

💾

2. Capacity & Cost Constraints

High-speed RAM is physically complex and expensive per gigabyte. A typical system has 16 GB of RAM, but a single modern game or video library can require hundreds of gigabytes. Secondary storage provides massive terabyte storage at a tiny fraction of the cost per gigabyte.

Why Fragmentation Does NOT Slow Down SSDs:

Because there is no physical arm to swing or platter to rotate, electrical signals can read any cell anywhere on the drive in the exact same 0.08 milliseconds. Non-contiguous blocks cause zero speed penalty!

Solid-State Reliability: SSDs store bits using trapped electrical charges inside floating-gate transistors. Because there are zero moving parts, SSDs are completely silent, draw less battery power, and will not break if dropped while reading.

Comparing Secondary Storage: Magnetic vs Solid-State vs Optical

Exam questions frequently ask you to recommend a storage type for a specific real-world scenario (e.g. an action camera, a backup server, or distributing software). You must evaluate across these 6 key characteristics:

Characteristic 💽 Magnetic (HDD / Tape) ⚡ Solid-State (SSD / USB Flash) 💿 Optical (CD / DVD / Blu-Ray)
1. Capacity Very High: 1 TB to 20+ TB. Massive storage for servers and backups. High: 256 GB to 8 TB. Plenty for OS, software, and games. Low: CD: 700 MB, DVD: 4.7 GB, Blu-ray: 25–50 GB.
2. Speed (Read/Write) Moderate: ~150 MB/s. Slower due to physical seek time and rotation. Very Fast: 500 MB/s to 7,000+ MB/s (NVMe). Instant access. Very Slow: ~10–30 MB/s. Mechanical laser tracking.
3. Portability Low: Bulky, heavy, requires delicate handling and SATA/USB cables. Excellent: Tiny, lightweight (M.2 sticks, USB flash thumb drives). High: Flat, lightweight discs, easily posted in envelopes.
4. Durability Poor: Dropping an HDD while running causes a catastrophic head crash. Very High: Shock-resistant. No moving parts to break if dropped. Moderate: Easily scratched or warped by sunlight and heat.
5. Reliability High: Excellent long-term retention if kept stationary and cool. High: Highly reliable, though cells have a finite write cycle limit. Low–Moderate: Discs can degrade or scratch after repeated handling.
6. Cost per GB Very Cheap: Around £0.015 per GB. Best for mass data archives. Moderate: Around £0.06 per GB. More expensive per gigabyte. Very Cheap per Unit: Pennies per blank disc, but low capacity.

CPU Architecture Revision Cards & Exam Traps

Core points to remember for AQA Paper 2 (Systems Architecture), common misconceptions, and mark schemes.

AQA 8525 §3.4.1 (Paper 2)

📌 Key Exam Traps & Core Concepts

AQA TRAP 1: REGISTERS

Never Confuse the MAR and the MDR

This is one of the most frequently lost marks on GCSE Computer Science papers. Remember their exact roles:

MAR (Memory Address Register):
• Holds the memory address (location) where data or an instruction is to be fetched from or written to.
• Connected to the Address Bus.
MDR (Memory Data Register):
• Holds the actual data value or instruction that has been read from RAM or is waiting to be written to RAM.
• Connected to the Data Bus.
💡 Memory Hook: MAR = Address (where to look); MDR = Data (what was found).
AQA TRAP 2: CPU PERFORMANCE

Why More Cores Does Not Guarantee Faster Performance

A common exam question asks why a quad-core CPU will not run four times faster than a single-core CPU:

• Software Parallelism: Many programs are written sequentially (Step 2 depends on Step 1). Extra cores remain idle if software cannot be split into concurrent threads.
• Overhead & Communication: The operating system must coordinate and synchronise threads across cores, consuming clock cycles.
• Resource Contention: All cores share the same memory bus and RAM. Accessing RAM creates a bottleneck.
AQA SPECIFICATION §3.4.1

The Stored Program Concept (Von Neumann)

✓ AQA Definition: In the Von Neumann architecture, both program instructions and data are stored together in the same physical memory (RAM) and fetched across shared system buses. Instructions are executed sequentially unless an explicit branch occurs.
PRIMARY MEMORY TRAP

Never Confuse RAM and ROM

Both are primary storage chips directly wired to the CPU, but their physical characteristics are opposites:

RAM (Random Access Memory):
• Volatile: Needs constant electrical power; wipes completely on shutdown.
• Read & Write: CPU continuously loads and modifies active apps, OS code, and open files.
ROM (Read-Only Memory):
• Non-Volatile: Retains data permanently when powered off.
• Read-Only: Factory burned. Stores BIOS/UEFI firmware and the Bootstrap Loader.
SECONDARY STORAGE ESSENTIALS

Why Secondary Storage is Needed & 6 Assessment Factors

RAM is volatile (temporary) and small in capacity. Secondary storage is non-volatile and provides high-capacity, long-term file retention.

The 6 Factors for Comparing Media:
1. Capacity: HDD (Huge TBs) > SSD (High GBs/TBs) > Optical (CD 700MB, DVD 4.7GB, BD 25GB).
2. Speed: SSD (instant, 500–7000 MB/s) > HDD (150 MB/s, physical seek) > Optical (~15 MB/s).
3. Portability: SSD/USB flash (small, light) > Optical discs > HDD (heavy, bulky).
4. Durability: SSD (shockproof) > Optical (scratches easily) > HDD (fragile head crash if dropped).
5. Reliability: SSD & HDD (high when treated well) > Optical (laser dye degrades).
6. Cost per GB: Optical & HDD (pennies per GB) vs SSD (higher cost per GB).
UTILITY SOFTWARE & EXAM TRAP

Defragmentation (HDD) vs Why You NEVER Defrag an SSD

A frequent exam question explores how file fragmentation affects performance:

• On a Magnetic HDD: Files become scattered across non-contiguous sectors over time. The mechanical arm must swing back and forth (seek time) to read all blocks, slowing down the drive. Defragmentation reorganises sectors contiguously so the file can be read in a single smooth rotation.
• On an SSD: Access time to any flash cell is identical (instant electrical pulse, zero seek time). Non-contiguous blocks do not slow it down. Furthermore, flash cells have a finite number of write cycles (P/E wear). Defragmenting an SSD needlessly writes gigabytes of data, wearing out the flash cells prematurely!
